# Проверка реализации

Проверки выполнялись 22 октября 2026 года. Продуктовая база не заполнялась тестовыми оценками. Browser QA использует отдельный SQLite-файл в `/tmp`.

## Автоматические проверки

- **Backend: 35 тестов.** Создание/чтение сессий, пустая аналитика, границы входных данных, CORS/Origin, persistence после повторного открытия SQLite, связи моделей, восстановление после рестарта, генерация всех сценариев, строгие категории, вычисление балла, отклонение выдуманных цитат, недостаточные данные, retry, настройки/cleanup SDK, PCM/transcript/interruption через WebSocket, плохие сообщения, сбой провайдера и concurrency limit.
- **Frontend: 13 тестов.** Пустой dashboard, обработка ошибки и retry, настройки тренировки, отсутствие ключа, отказ микрофона без создания сессии, пустая история, insufficient-data report; выполнение реального исходника worklet с 16000/44100/48000 Hz и проверкой частоты, размера/порядка байтов, clipping, отправки последнего неполного кадра и очистки буфера после mute.
- **Production build:** TypeScript + Vite, разделение страниц на динамические chunks.
- **Browser QA:** Chrome desktop/mobile, навигация, REST с настоящим backend, отсутствие горизонтального overflow, отказ микрофона, голосовой путь с искусственным устройством Chrome и тестовым WebSocket, mute/unmute/end, рендер полноценного отчёта. Эти тесты не обращаются к Gemini.
- npm dependency audit после обновления dev-инструментов: **0 обнаруженных уязвимостей** на момент установки. Это не полноценный security audit продукта.

## Что не проверено без реального Gemini API key

- Авторизация и доступ к конкретным выбранным моделям, ограничения проекта/региона/квоты.
- Настоящий Gemini Live opening, генерация речи и input/output transcription выбранной моделью.
- Качество распознавания русского и английского, задержка, acoustic echo cancellation, перебивания в реальном разговоре.
- Реальный structured-output ответ оценочной модели, качество обратной связи и стабильность доказательств.
- Точность последних фрагментов транскрипции при завершении реальной сессии.
- Safari, Firefox, физические микрофоны/гарнитуры, мобильные браузеры и плохая сеть.

## Приёмка с ключом

1. Заполнить три переменные Gemini. Перезапустить backend; проверить `ai_ready: true`. Это только конфигурационная готовность, а не проверка API key.
2. Выбрать English, price objection, skeptical, medium, описание с реальной ценой. Подключить наушники, разрешить микрофон.
3. Убедиться, что клиент начинает разговор в роли покупателя. Сказать минимум две содержательные реплики, всего больше 30 слов, получить минимум два ответа.
4. Сопоставить UI-transcript с услышанным разговором. Проверить роли, отсутствие служебной стартовой реплики в тексте продавца.
5. Перебить клиента во время ответа; проверить остановку старой очереди звука. Проверить mute/unmute и продолжение разговора.
6. После завершённого ответа нажать End session. Проверить отсутствие активного индикатора микрофона, готовность отчёта, балл `2 * sum(categories)` и точное совпадение цитат.
7. Перезагрузить страницу и backend, открыть тот же отчёт через историю; проверить сохранность данных и dashboard.
8. Повторить на русском, с analytical/hard и другим продуктом. Проверить соответствие поведения настройкам.
9. Проверить очень короткий разговор: `insufficient_data`, без случайного балла.
10. Проверить неправильный ключ/модель, отказ микрофона, обрыв сети и закрытие вкладки: понятная ошибка, освобождение slot, отсутствие бесконечного микрофона и вымышленного fallback.
11. Проверить ошибку evaluation и повтор с исправленной конфигурацией; transcript не должен изменяться или заменяться.

Демонстрация внешнему клиенту требует успешного прохождения этой ручной приёмки. Автотесты с mocks её не заменяют.
